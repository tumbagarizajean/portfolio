Vessel Documentation Process Redesign (Free Time Determination)

Role: Process Expert · Tools: Excel/VBA, internal terminal & documentation systems · Result: ~6 hrs → ~2 hrs daily; 8–9 tools → 3 per vessel

System names and internal tool details are generalized to protect employer confidentiality. The workflow structure and results are real.

The problem

A daily documentation process had to be completed for every vessel handled — typically 4 to 6 a day, sometimes more. Each vessel took roughly an hour or longer depending on how many bills of lading were loaded against it, for a total daily processing time of around six hours. The slowest part wasn't the decision-making — it was the navigation: each vessel required opening and cross-referencing 8 to 9 different tools and source systems, one at a time.

What I built

Instead of opening each source system per vessel, I consolidated the data those systems held into a single master file, updated on a schedule, and built a macro that pulled from that master rather than re-querying each source live.

Before: vessel arrives → open Tool 1 → open Tool 2 → … → open Tool 8/9 → cross-reference manually → determine free time → document result → repeat per vessel, ~1 hour+ each.

After: vessel arrives → macro pulls the relevant data from the consolidated master → remaining manual step is verifying against the one or two systems that need a live check → document result. Down to roughly 20–30 minutes per vessel.

Design decisions worth calling out

  • Consolidate before you automate. The biggest win wasn't the macro logic — it was recognizing that most of the 8–9 tool lookups were repeated queries against data that didn't change vessel-to-vessel within the same day, and could be centralized once instead of re-fetched every time.
  • Keep the genuinely live step live. One tool in the original workflow reflects real-time terminal status, so it stays a manual check — automating a stale copy of it would make results less reliable, not more.
  • Design for the busy day, not the average day. With volume ranging from 4 to 6+ vessels, the goal was a workflow that held up on the high-volume days, since that's when manual process breaks down fastest.

What I'd apply elsewhere

When a process is slow because of lookup overhead rather than decision complexity, the fix is usually consolidation, not more automation logic. Find what's being re-fetched unnecessarily before automating the decision itself.
