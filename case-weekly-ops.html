Weekly Operations Report — Excel/VBA Automation

Role: Reporting & Automation Lead · Tools: Excel, VBA, Outlook · Result: 1–2 hrs → ~15 min per cycle

Demo runs on fabricated data with invented company names and regions. It reproduces the method of an automation from a previous role, not that employer's data or systems.

The problem

A recurring task report had to be produced every Monday for two regions. The manual routine: download a raw export, filter and paste each region's slice into its own file, hand-build summary tables (top task types, top accounts, overdue counts), then retype the headline numbers into an email. It took an hour or two, and it was easy for a number in the email to drift from the number in the attachment.

What I built

A macro-enabled workbook that validates the raw export, splits it by region, builds the summaries, and generates the email body — down to about 15 minutes end to end.

Pipeline: raw export → header validation → split by region → build summaries (top task types, top accounts, headline stats) → auto-split into a separate file per region → generate email body

Design decisions worth calling out

  • Validate before processing. The macro checks every required column exists before touching anything, and names what's missing. A changed export layout was the most common real failure, and a silent wrong answer is worse than a clear stop.
  • Find columns by header name, not position. Hardcoded column letters break the first time someone adds a field. Every lookup resolves the header text at runtime.
  • Parameters live on a control sheet, not in the code. Reporting week, thresholds, and list sizes sit on a separate sheet so a non-technical colleague can adjust them without opening the VBA editor.
  • Generate the email from the same numbers as the report. The old process re-typed figures by hand; this one can't let the email and the attachment disagree.
  • Human stays in the loop at the end. The macro stops at a reviewable draft — distribution is deliberately manual.
